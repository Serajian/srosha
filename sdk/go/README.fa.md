# srosha — کتابخانهٔ Go

[English](README.md) · **فارسی**

کلاینتِ [srosha](../../README.md)، یک سرویسِ **ناهمگام** (asynchronous) برای
اطلاع‌رسانی. شما یک بار پیام را تحویل می‌دهید؛ srosha بعداً و بیرون از مسیرِ
درخواستِ شما آن را روی email، Telegram، Bale، WhatsApp، Matrix، FCM و APNs
می‌فرستد و در هر کانال جداگانه تلاشِ دوباره می‌کند.

---

## ۱ — قبل از اینکه بتوانید چیزی بفرستید

سه چیز لازم دارید، به همین ترتیب:

| | | |
| --- | --- | --- |
| ۱ | **آدرس** | جایی که srosha گوش می‌دهد — یک نام، یا `host:port` |
| ۲ | **کلیدِ API** | شما را می‌شناساند؛ روی هر تماس می‌رود |
| ۳ | **هویتِ فرستنده** | پیام از طرفِ **کدام** بات یا حسابِ ایمیل برود |

اگر srosha روی ۴۴۳ باشد — یعنی همان‌جایی که پشتِ یک خاتمه‌دهندهٔ TLS می‌نشیند —
نامِ تنها کافی است: `api.srosha.dev` و `api.srosha.dev:443` یک هدفِ یکسان‌اند.
پورت را وقتی بدهید که چیزِ دیگری باشد — مثلاً `gateway:50051` برای listener ــِ
بدونِ رمزنگاری داخلِ شبکهٔ خودِ srosha.

سومی در ابتدا اختیاری است: اگر اپراتور برای srosha هویتی تنظیم کرده باشد، از
طرفِ خودش می‌فرستد و شما بعداً مالِ خودتان را اضافه می‌کنید. دو تای اول اختیاری
نیستند.

## ۲ — گرفتنِ کلیدِ API

**خودتان نمی‌توانید بسازید، و ثبت‌نامی وجود ندارد.** srosha نه API مدیریتی دارد
نه کنسول: هرکس آن را اجرا می‌کند، source شما را می‌سازد و کلید را بیرون از این
سرویس به شما می‌دهد. از او بخواهید.

<details>
<summary>اگر خودتان آن اپراتور هستید، امروز این را اجرا می‌کنید</summary>

> **این موقتی است.** چیزِ بعدی که ساخته می‌شود یک پنلِ مدیریت است: ادمین
> مشخصاتِ یک source را می‌گیرد، رکورد را می‌سازد، و کلید صادر و برایش فرستاده
> می‌شود. اینکه چه چیزی گرفته می‌شود و کلید چطور می‌رسد، سرِ طراحیِ همان پنل
> تصمیم گرفته می‌شود. تا آن موقع، دو دستورِ SQL است.

کلید یعنی `srosha_` به‌علاوهٔ ۴۳ کاراکترِ base64url، و فقط SHA-256 آن ذخیره
می‌شود؛ پس **کلید یک بار نشان داده می‌شود و هرگز دوباره در دسترس نیست.**

```bash
# ۱. ساختِ کلید. همین حالا به مشتری بدهیدش -- بازیابی‌شدنی نیست.
KEY="srosha_$(head -c 32 /dev/urandom | base64 | tr '+/' '-_' | tr -d '=')"
HASH=$(printf '%s' "$KEY" | shasum -a 256 | cut -d' ' -f1)
echo "$KEY"

# ۲. دو شناسه. هر شناسه در srosha یک ULID است: ۲۶ کاراکتر از Crockford
#    base32، که حروفِ I و L و O و U را ندارد. دستی نوشتن و برداشتنِ حرفی که
#    درست به نظر می‌رسد، همان راهی است که به ulid_check می‌خورید.
mkid() { python3 -c "
import time, secrets
A = '0123456789ABCDEFGHJKMNPQRSTVWXYZ'
n = (int(time.time() * 1000) << 80) | secrets.randbits(80)
print(''.join(A[(n >> (5 * (25 - i))) & 31] for i in range(26)))"; }
SOURCE_ID=$(mkid); KEY_ID=$(mkid)

# ۳. ساختِ source و کلید
psql "$NOTIF_DB_DSN" <<SQL
INSERT INTO sources (id, name, max_priority, is_active, allow_custom_address,
                     created_at, updated_at)
VALUES ('$SOURCE_ID', 'acme', 'HIGH', true, true, now(), now());

INSERT INTO api_keys (id, source_id, key_hash, label, created_at)
VALUES ('$KEY_ID', '$SOURCE_ID', '$HASH', 'acme prod', now());
SQL
```

دو فیلد تعیین می‌کنند که آن source اجازهٔ چه کاری دارد:

- `max_priority` سقفِ اوست. خواستنِ بالاتر **خطا نیست** — پیام روی سقف پذیرفته
  می‌شود و جواب می‌گوید که پایین آورده شد.
- `allow_custom_address` اگر false باشد، فقط می‌تواند به آدرس‌هایی بفرستد که
  برایش تنظیم شده — و همین محدود می‌کند که کلیدِ لو رفته تا کجا می‌رسد.

یک source می‌تواند **همزمان دو کلید** داشته باشد، و این همان چیزی است که چرخاندنِ
کلید را بدونِ قطعی ممکن می‌کند: دومی را بده، بگذار جابه‌جا شوند، اولی را باطل کن.

</details>

کلید را در مخزنِ کدتان نگذارید. یک اعتبارنامهٔ **حامل** (bearer) است: هرکس آن را
داشته باشد می‌تواند به‌جای شما بفرستد.

## ۳ — نصب

```bash
go get github.com/Serajian/srosha/sdk/go
```

Go نسخهٔ ۱٫۲۳ به بالا — عمداً پایین‌تر از نسخهٔ خودِ سرویس، تا یک SDK هرگز شما را
مجبور به ارتقای زنجیرهٔ ابزارتان نکند.

## ۴ — اولین پیام

```go
package main

import (
	"context"
	"log"
	"os"

	"github.com/Serajian/srosha/sdk/go/srosha"
)

func main() {
	ctx := context.Background()

	c, err := srosha.New(ctx, "api.srosha.acme.test", os.Getenv("SROSHA_API_KEY"))
	if err != nil {
		log.Fatal(err)
	}
	defer func() { _ = c.Close() }()

	r, err := c.Submit(ctx, srosha.Message{
		Title:  "سفارش شما ارسال شد",
		Body:   "کد رهگیری: ۱۲۳",
		Routes: []srosha.Route{srosha.Email("customer@example.com")},
	})
	if err != nil {
		log.Fatal(err)
	}
	log.Println("پذیرفته شد:", r.ID)
}
```

**از داخلِ شبکهٔ خودِ srosha وصل می‌شوید؟** آنجا listener ــِ gRPC آن TLS ندارد،
پس باید صریح بگویید:

```go
srosha.New(ctx, "gateway:50051", key, srosha.WithInsecure())
```

هر سه تکهٔ آن با حالتِ بیرونی فرق دارد، و همه به یک دلیل:

- **`gateway`** نامِ سرویسِ srosha در compose است که DNS ــِ خودِ Docker حلش
  می‌کند — همان‌طور که خودِ srosha به `postgres` و `nats` می‌رسد. دامنه نیست و
  Traefik ای جلویش نیست.
- **`:50051`** لازم است چون پورتِ gRPC هرگز منتشر نمی‌شود. روی شبکهٔ خصوصی
  `expose:` است، یعنی برای همسایه‌ها هست و برای هیچ‌کسِ دیگر.
- **`WithInsecure()`** چون TLS سرِ Traefik خاتمه می‌یابد و listener ــِ پشتش
  بدونِ رمزنگاری حرف می‌زند. بدونِ آن، کلاینت handshake ای را شروع می‌کند که
  کسی جوابش را نمی‌دهد.

پیش‌فرض TLS است و این عمدی است، و SDK عمداً از روی پورت **حدس نمی‌زند**. یادت
برود `WithInsecure()` را بنویسی، همان‌جا و با صدای بلند شکست می‌خورد؛ حدس زدن
یک روز بی‌صدا چیزی را لخت می‌فرستاد به جایی که فکر می‌کردی جای دیگری است.

از داخلِ شبکه **می‌شود** با دامنهٔ عمومی هم به srosha رسید — ولی یعنی از شبکهٔ
خصوصی بیرون بروی، به Traefik برسی و برگردی، برای TLS ای که لازم نداری. و وقتی
دامنه مشکل داشته باشد قطع می‌شوی، در حالی که همسایه‌ات سالم است.

### حدودتان را قبل از خوردن به آن‌ها بدانید

```go
me, err := c.Whoami(ctx)
```

دو تا از چیزهای زیر را جورِ دیگری فقط با اشتباه کردن می‌شود فهمید: سقفِ اولویت
به‌شکلِ پیامی که بی‌صدا پایین آورده شده، و مدتِ نگه‌داشت به‌شکلِ فهرستی که رد شده.

```go
me.ID                  // موقعِ کمک خواستن همین را بگویید
me.Name
me.MaxPriority         // بالاتر از آن پایین آورده می‌شود، رد نمی‌شود
me.AllowCustomAddress  // false یعنی DefaultAddresses کلِ جایی است که می‌رسید
me.DefaultAddresses    // به‌ازای هر کانال، آنچه route ــِ بدونِ آدرس به آن می‌رسد
me.Retention           // یک فهرست از این عقب‌تر نمی‌تواند برود
me.MaxWindow()         // همان، به‌شکلِ بلندترین Window ای که قبول می‌شود
me.RateLimitPerMinute  // به‌ازای هر source شمرده می‌شود
```

و ارزان‌ترین راه است برای فهمیدنِ اینکه آدرس درست است و کلید کار می‌کند. کلاینت
تنبل وصل می‌شود، پس بدونِ این، اولین خبر از غلط بودنِ هرکدام سرِ **اولین پیامی که
مهم بوده** می‌رسد:

```go
c, err := srosha.New(ctx, addr, key)
if err != nil {
	return err
}
if me, err := c.Whoami(ctx); err != nil {
	log.Warn("srosha unreachable at startup", "err", err)
} else {
	log.Info("srosha", "as", me.Name, "ceiling", me.MaxPriority)
}
```

**وقتی یک پروسه بالا می‌آید صدایش بزنید، نه روی تایمر.** بررسیِ سلامت نیست: مثلِ
هر تماسِ دیگری از سهمیهٔ rate limit شما کم می‌کند، و جوابِ موفق دربارهٔ تماسِ بعدی
هیچ نمی‌گوید — کلیدها باطل می‌شوند و شبکه‌ها بینِ دو تماس قطع می‌شوند.

و **اگر شکست خورد، از بالا آمدن سر باز نزنید.** srosha ناهمگام است؛ اپلیکیشنی که
وقتی srosha لحظه‌ای پایین است بالا نمی‌آید، بدتر از اپلیکیشنی است که هشدار را
log می‌کند و کارش را ادامه می‌دهد.

### کلِ پیام

هرچه `Message` حمل می‌کند، و هر فیلد برای چیست:

```go
c.Submit(ctx, srosha.Message{
	// اختیاری. خالی یعنی برای همین تماس یکی ساخته می‌شود، و همین است که
	// تلاشِ دوباره را امن می‌کند. مالِ خودتان را وقتی بگذارید که این تضمین را
	// بینِ تماس‌ها می‌خواهید -- بخشِ ۹.
	IdempotencyKey: "order-42",

	Title: "سفارش شما ارسال شد",
	Body:  "کد رهگیری: ۱۲۳",

	// اختیاری. بالاتر از سقفتان پذیرفته و پایین آورده می‌شود، هرگز رد نمی‌شود؛
	// جواب می‌گوید که این اتفاق افتاده.
	Priority: srosha.PriorityHigh,

	// اختیاری. صفر یعنی هرگز منقضی نمی‌شود. بعد از این، پیام ارزشِ فرستادن
	// ندارد و تحویلی که هنوز منتظر است با FailureExpired شکست می‌خورد.
	ExpireAt: time.Now().Add(2 * time.Hour),

	// اختیاری. دست‌نخورده حمل و برگردانده می‌شود -- شمارهٔ سفارش، یک trace id.
	// دو کانال آن را می‌خوانند هم؛ پایین‌تر.
	Metadata: map[string]string{"order_id": "42"},

	// حداقل یکی. هرکدام یک تحویلِ جدا با سرنوشتِ خودش است.
	Routes: []srosha.Route{
		srosha.Email("a@b.test"),
		srosha.Telegram("123456789").From("marketing"),
	},
})
```

فقط `Body` و `Routes` اجباری‌اند.

### عنوان و متن، به‌ازای هر کانال

یک جفت فیلد هست و هفت کانال، و همه‌شان دو جا برای گذاشتنشان ندارند.

| | |
| --- | --- |
| `Email` | `Title` همان موضوعِ نامه است |
| `FCM`، `APNs` | دو فیلدِ جدا، که پلتفرم متفاوت نمایششان می‌دهد |
| بقیه | یک فیلدِ متنی، پس با یک خطِ خالی به هم چسبانده می‌شوند |

پس عنوانی که به‌عنوانِ موضوعِ نامه خوب بخواند، به‌عنوانِ خطِ اولِ پررنگ هم خوب
می‌خواند. خالی بگذاریدش و فقط متن فرستاده می‌شود.

### شکل‌هایی که یک پیام می‌گیرد

**یک نفر، از چند راه** — هر route یک تحویلِ جدا با سرنوشتِ خودش است، و شکست خوردنِ
یکی جلوی بقیه را نمی‌گیرد:

```go
Routes: []srosha.Route{
	srosha.Email("a@b.test"),
	srosha.Telegram("123456789"),
	srosha.APNs(deviceToken),
}
```

**چند نفر، از یک راه:**

```go
Routes: []srosha.Route{
	srosha.Email("a@acme.test"),
	srosha.Email("b@acme.test"),
}
```

**از هویتِ مشخصی از خودتان**، وقتی یک کانال بیش از یکی دارد:

```go
srosha.Telegram("123456789").From("marketing")
```

**روی کانالی که این نسخه سازنده‌ای برایش ندارد** — سرویسِ جدیدتر:

```go
srosha.To("sms", "+989121234567")
```

### metadata ای که دو کانال واقعاً می‌خوانند

`Metadata` مالِ شماست و srosha هرگز تفسیرش نمی‌کند. دو adapter داخلش دنبالِ چیزی
می‌گردند که API خودشان لازم دارد، و هیچ کانالِ دیگری تحت تأثیر نیست.

**WhatsApp** بیرون از پنجره‌ای که گیرنده باز کرده متنِ آزاد قبول نمی‌کند و
به‌جایش یک قالبِ تأییدشده می‌خواهد. **شما** تصمیم می‌گیرید کدام، چون فقط شما
می‌دانید که او اخیراً به شما نوشته یا نه:

| کلید | |
| --- | --- |
| `template` | نامِ قالبِ تأییدشده. بودنش یعنی قالب، نبودنش یعنی متن |
| `template_language` | پیش‌فرض `en_US` |
| `template_params` | یک **آرایهٔ JSON** از رشته‌ها، به ترتیب |

```go
Metadata: map[string]string{
	"template":        "order_shipped",
	"template_params": `["Ali","123"]`,
}
```

**FCM** کلِ نقشه را به‌عنوانِ `data` ــِ پوش می‌برد، که همان چیزی است که اپِ شما
موقعِ باز کردنِ اعلان می‌خواند. کلیدهایی که FCM برای خودش نگه داشته — `from`،
`message_type`، `notification`، و هرچه با `google` یا `gcm` شروع شود — قبل از
تماس **رد می‌شوند**، نه اینکه بی‌صدا حذف شوند.

**APNs** نقشه را کنارِ کلیدِ خودِ اپل یعنی `aps` می‌گذارد. خودِ `aps` به همان دلیل
رد می‌شود.

هر جای دیگری ذخیره می‌شود، با `Get` برمی‌گردد، و بیشتر از این کاری با آن نیست.

### «پذیرفته شد» یعنی چه

`Submit` به‌محضِ اینکه پیام **ذخیره** شد جواب می‌دهد، نه وقتی تحویل داده شد. کلِ
طراحی همین است: به‌اندازهٔ نوشتنِ یک سطر طول می‌کشد، نه به‌اندازهٔ جواب دادنِ یک
provider.

پس `r.ID` یعنی «گرفتیمش و تلاش می‌کنیم»، و نه بیشتر.

سه فیلدِ جواب ارزشِ خواندن دارند:

```go
r.ID          // شناسهٔ پیام -- بعداً با همین سراغش را می‌گیرید
r.Priority    // در عمل با چه اولویتی فرستاده می‌شود
r.Downgraded  // بالاتر از سقفتان خواستید؛ پایین آورده شد، رد نشد
r.Duplicate   // این idempotency key قبلاً استفاده شده؛ چیز تازه‌ای ساخته نشد
```

## ۵ — بفهمید چه شد

```go
got, err := c.Get(ctx, r.ID)
for _, d := range got.Deliveries {
	log.Println(d.Channel, d.Address, d.Status, d.Reason)
}
```

به ازای هر گیرنده یک `Delivery`، هرکدام با سرنوشتِ خودش.

| `Status` | |
| --- | --- |
| `StatusPending` | هنوز در حالِ تلاش |
| `StatusSent` | یک provider گرفتش |
| `StatusFailed` | دیگر تلاش نمی‌شود؛ `Reason` می‌گوید چرا |

`StatusSent` یعنی **provider** تحویل گرفت. اینکه گوشیِ کسی روشن شد یا نه چیزی
است که فقط provider می‌داند؛ `ProviderMessageID` همان دستگیره‌ای است که برای
پرسیدن از او لازم دارید.

| `Reason` | چه کار کنید |
| --- | --- |
| `FailureNotReachable` | **تنها موردی که کاری از شما برمی‌آید.** provider خودِ **گیرنده** را رد کرد: توکنِ مردهٔ دستگاه، شماره‌ای که روی آن سرویس نیست، اتاقی که دعوت نشده‌اید. دیگر آنجا نفرستید. |
| `FailureNoSender` | برای آن کانال هیچ هویتی تنظیم نشده — بخشِ ۷ |
| `FailurePermanent` | provider پیام را رد کرد و دوباره هم می‌کند |
| `FailureMaxAttempts` | به‌اندازه‌ای که srosha تلاش می‌کند، تلاش شد |
| `FailureExpired` | `ExpireAt` ــِ خودتان زودتر رسید |

برای دیدنِ آنچه اخیراً فرستاده‌اید:

```go
for n, err := range c.List(ctx, srosha.LastDay) {
	if err != nil {
		return err
	}
	log.Println(n.ID, n.Title, n.CreatedAt)
}
```

صفحه‌ها **وقتی حلقه بخواهد** گرفته می‌شوند، پس `break` جلوی درخواست‌های بعدی را
می‌گیرد.

بازهٔ زمانی یک مجموعهٔ بسته است — `LastHour`، `LastDay`، `LastWeek`،
`LastMonth`، `Everything` — و نه دو زمانِ دلخواه، چون srosha بایگانی نیست: بعد از
مدتِ نگه‌داشت پیام پاک می‌شود، و یک بازهٔ بازتر جوابِ ناقص می‌داد بدونِ اینکه چیزی
بگوید. `Everything` یعنی «تا هرجا که این استقرار نگه داشته»، که تنها جوابی است
که با هر تنظیمی درست است. بلندتر از نگه‌داشت بخواهید، `ErrInvalidRequest`
می‌گیرید که حدِ واقعی را می‌گوید.

## ۶ — آدرس، به‌ازای هر کانال

آدرسی که شکلش غلط باشد سرِ `Submit` رد می‌شود، **قبل از اینکه چیزی ذخیره شود** —
پس یک اشتباه برایتان یک خطا هزینه دارد، نه یک تحویلِ شکست‌خورده چند ساعت بعد.

| کانال | آدرس | نمونه |
| --- | --- | --- |
| `Email` | یک نشانیِ ایمیل | `a@b.test` |
| `Telegram`, `Bale` | شناسهٔ عددیِ چت، یا `@name` **فقط برای کانالِ عمومی** — هرگز برای یک شخص، هر username ای که داشته باشد | `123456789`، `-100123`، `@acmenews` |
| `WhatsApp` | E.164، یعنی `+` و ۸ تا ۱۵ رقم | `+989121234567` |
| `Matrix` | یک **اتاق**، نه یک کاربر. Matrix اصلاً «به این شخص بفرست» ندارد | `!abc:matrix.org` |
| `FCM` | توکنِ دستگاهِ اندروید، ۳۲ تا ۴۰۹۶ کاراکتر | `cXy…` |
| `APNs` | توکنِ دستگاهِ اپل، هگزادسیمال، ۳۲ تا ۲۰۰ کاراکتر | `a1b2c3…` |

`srosha.To(channel, address)` برای کانالی است که این نسخه هنوز سازنده‌ای برایش
ندارد.

## ۷ — فرستادن از طرفِ خودتان

به‌طورِ پیش‌فرض پیام از هویتِ خودِ srosha بیرون می‌رود، اگر اپراتور برای آن کانال
یکی تنظیم کرده باشد. برای فرستادن از باتِ خودتان یا حسابِ ایمیلِ خودتان، ثبتش
کنید — **یک بار**:

```go
_, err := c.Credentials.Register(ctx, srosha.Registration{
	Name:       "alerts",
	Default:    true,
	Credential: srosha.TelegramCredential{Token: botToken},
})
```

بعد از آن دیگر هرگز اسمش را نمی‌برید. `Submit` یک **کانال** را نام می‌برد نه یک
هویت، و پیش‌فرض استفاده می‌شود:

```go
c.Submit(ctx, srosha.Message{
	Body:   "…",
	Routes: []srosha.Route{srosha.Telegram("123456789")},  // از "alerts" می‌رود
})
```

فقط وقتی یک کانال بیش از یک هویت دارد، می‌گویید کدام:

```go
srosha.Telegram("123456789").From("marketing")
```

نام‌ها حروفِ کوچکِ انگلیسی، رقم و خط تیره‌اند، چون در url و در کلیدِ پیکربندی
می‌روند. **و به‌ازای هر کانال یکتا هستند، نه به‌ازای هر source** — `alerts` روی
Telegram و `alerts` روی email دو هویتِ متفاوت‌اند.

### «یک بار» یعنی یک بار، و دلیلش این است

وسوسه‌انگیز است که `Register` را در راه‌اندازیِ اپلیکیشنتان بگذارید تا پیکربندی
هر بار اعمال شود. **نگذارید.** ثبتِ دوبارهٔ یک نام روی یک کانال `ErrDuplicate`
می‌دهد، و تماسِ دوم **هیچ چیز** را عوض نمی‌کند: نه رازِ ذخیره‌شده، نه پیش‌فرض
بودنش، حتی نه `updated_at` ــِ آن سطر. کلِ درخواست رد می‌شود نه اینکه نیمه‌کاره
اعمال شود، پس هرگز مخرب نیست — ولی سه پیامد دارد که باید بدانید.

- اگر کدتان آن خطا را کشنده بداند، **اپتان بعد از بارِ اول بالا نمی‌آید.**
- راز مجبور است برای همیشه در محیطِ اپلیکیشنتان بماند. نکتهٔ «یک بار» همین است
  که بعدش srosha آن را سربسته نگه می‌دارد و اپِ شما دیگر لازمش ندارد — یک جای
  کمتر که بتواند از آن لو برود.
- و آن یکیِ خاموش: روزی توکن را عوض می‌کنید، و هر ری‌استارت توکنِ **قدیمی** را
  دوباره ثبت می‌کند، `ErrDuplicate` می‌گیرد، نادیده‌اش می‌گیرد، و شما را در این
  باور می‌گذارد که کدتان مالکِ توکن است در حالی که نیست. هیچ چیز نمی‌گوید که آن
  دو از هم جدا شده‌اند.

یک بار انجامش دهید، از جایی که اپلیکیشنتان نیست — یک دستورِ کوچکِ ادمین، یا
دستی. اگر واقعاً باید سرِ راه‌اندازی باشد، تکراری بودن را تحمل کنید:

```go
if err := register(); err != nil && !errors.Is(err, srosha.ErrDuplicate) {
	return err
}
```

اول `List` گرفتن و بعد ثبت کردن، مرتب‌تر به نظر می‌رسد و بهتر نیست: دو نمونه که
همزمان بالا می‌آیند هر دو «نبود» می‌بینند و باز یکی `ErrDuplicate` می‌گیرد.
داور همان unique index است، نه بررسیِ شما.

**نه این کتابخانه و نه srosha، `Register` را برایتان idempotent نمی‌کنند.** تنها
راهش نادیده گرفتنِ رازی است که با رازِ ذخیره‌شده فرق دارد — و اصلاً نمی‌تواند
تشخیصش دهد، چون srosha هرگز رازی برنمی‌گرداند. سکوت در آنجا دقیقاً همان پیامدِ
سوم است، فقط جابه‌جا شده به جایی که دیدنش سخت‌تر است. وقتی راز عوض می‌شود، بگویید:
`Rotate` برای همین است.

### هر کانال چه می‌خواهد

| | |
| --- | --- |
| `TelegramCredential`، `BaleCredential` | `Token` — از BotFather |
| `FCMCredential` | `ServiceAccount` — کلِ فایلِ json ــِ service account، نه base64 آن |
| `SMTPCredential` | `Host`، `Port`، `Username`، `From`، `Password`. پورتِ ۴۶۵ یعنی TLS از اولین بایت؛ هر چیزِ دیگر STARTTLS. صفر یعنی ۵۸۷ |
| `MatrixCredential` | `Homeserver` (https، بدون path) و `Token` |
| `WhatsAppCredential` | `PhoneNumberID` — شناسهٔ Meta برای آن شماره، نه خودِ شماره — و `Token` |
| `APNsCredential` | `Key` (محتوای فایلِ `.p8`)، `KeyID`، `TeamID`، `Topic` (bundle id ــِ اپتان) و `Environment`. `Environment` را خالی بگذارید تا production شود، که همان چیزی است که اپِ منتشرشده استفاده می‌کند — توکنی که از بیلدِ development آمده برای production ناشناس است و به‌شکلِ `FailureNotReachable` برمی‌گردد |
| `RawCredential` | کانالی که این نسخه تایپی برایش ندارد: `Channel`، `Config` ــِ json، و `Secret` |

هیچ‌کدامشان رازشان را چاپ نمی‌کنند، نه با `%v` و نه با `json.Marshal`.

### تغییر دادنشان بعداً

```go
c.Credentials.Rotate(ctx, id, newSecret)   // رازِ تازه، همان نام
c.Credentials.Update(ctx, id, cred)        // تنظیماتِ تازه، همان راز
```

**`Rotate` همان چیزی است که توکنِ لو رفته لازم دارد.** اگر به‌جایش یک هویتِ دوم
ثبت کنید، هر پیامی که هنوز نامِ قبلی را می‌برد شکست می‌خورد — و یک نشتی تبدیل به
یک تغییرِ کد می‌شود.

`Update` **فقط نیمهٔ تنظیمات** را می‌فرستد؛ رازی که روی credential ــِ تحویلی
بگذارید نادیده می‌شود. و کلِ سندِ تنظیمات را جایگزین می‌کند نه patch، پس همهٔ
فیلدها را بفرستید نه فقط آنکه عوض شده.

`Deactivate` جلوی استفاده از یک هویت را می‌گیرد بدونِ فراموش کردنش، پس روشن کردنش
دوباره یک ثبتِ تازه نیست. هیچ چیز اینجا حذف نمی‌شود. اگر پیش‌فرض دستِ او بود، آن
کانال بدونِ پیش‌فرض می‌ماند تا `SetDefault` یکی را نام ببرد — srosha حدس نمی‌زند
که کدام باید جایش را بگیرد.

## ۸ — به‌جای پرسیدن، به شما گفته شود

```go
c.Webhooks.Register(ctx, "https://acme.test/srosha")
```

بعد از آن srosha سرنوشتِ نهاییِ هر تحویل را POST می‌کند. آدرس باید https باشد و
نباید به داخلِ شبکهٔ خودِ srosha اشاره کند.

هر callback با **HMAC-SHA256 روی `<timestamp>.<body>`** امضا می‌شود، با رازی که
بیرون از این سرویس به شما داده می‌شود.

**قبل از اعتماد، بررسی‌اش کنید.** یک callback ــِ بررسی‌نشده یعنی هر چیزی که هرکسی
به آن url فرستاده.

```go
// یک بار، سرِ راه‌اندازی.
v, err := srosha.NewVerifier(os.Getenv("SROSHA_WEBHOOK_SECRET"))

func handler(w http.ResponseWriter, r *http.Request) {
	body, err := io.ReadAll(r.Body)
	if err != nil {
		w.WriteHeader(http.StatusBadRequest)
		return
	}

	cb, err := v.Verify(r.Header, body)
	if err != nil {
		// نگویید کدام بررسی شکست خورد. کسی که دارد حدس می‌زند لازم نیست
		// بداند چقدر نزدیک شده.
		w.WriteHeader(http.StatusUnauthorized)
		return
	}

	for _, d := range cb.Deliveries {
		fmt.Println(d.Channel, d.Address, d.Status, d.Reason)
	}
	w.WriteHeader(http.StatusOK)
}
```

سه چیز را بررسی می‌کند، و هرکدام مسئلهٔ متفاوتی‌اند:

| | |
| --- | --- |
| `ErrSignatureMissing` | اصلاً امضایی نیست. کسی که srosha نیست |
| `ErrSignatureInvalid` | امضا نمی‌خواند. کسی که خودش را srosha جا زده، یا بدنه در راه عوض شده |
| `ErrCallbackTooOld` | اصیل است، ولی خیلی وقت پیش امضا شده. تقریباً همیشه replay — علتِ دیگرش ساعتِ خودتان است |

**بدنه را خام بخوانید و دست‌نخورده بدهید.** امضا روی دقیقاً همان بایت‌هایی است که
srosha فرستاده، پس بدنه‌ای که دوباره encode شده، مرتب چاپ شده، یا از یک decoder
ــِ json رد شده، تأیید نمی‌شود. این باگ نیست؛ همان کارِ امضاست.

پنجرهٔ کهنگی پیش‌فرض پنج دقیقه است، و **دقیقاً همان مدتی است که یک callback ــِ
ضبط‌شده قابلِ replay می‌ماند**. `srosha.WithTolerance(d)` بازترش می‌کند — فقط
برای ساعتی که نمی‌توانید درستش کنید.

`Verify` عمداً یک تابع است نه یک `http.Handler`: وصل کردنش به یک route سه خط
است و مالِ همان framework ای است که استفاده می‌کنید.

callback بهترین-تلاش است: بعد از یک حد دوباره تلاش نمی‌شود، و شکستِ کافی خاموشش
می‌کند. `Get` و `List` مسیرِ قابلِ اتکا هستند — webhook شما را از polling بی‌نیاز
می‌کند، جایش را نمی‌گیرد. به‌محضِ اینکه callback را گرفتید `2xx` بدهید، نه بعد از
اینکه کارتان با آن تمام شد.

## ۹ — خطاها

```go
switch {
case errors.Is(err, srosha.ErrRateLimited):
	// درخواستِ زیاد. کلاینت خودش عقب می‌کشد مگر retry را خاموش کرده باشید؛
	// اگر این را می‌بینید یعنی تلاش‌ها تمام شده
case errors.Is(err, srosha.ErrInvalidRequest):
	// درخواست غلط است و دوباره هم غلط خواهد بود. err.Error() حرفِ خودِ
	// srosha را حمل می‌کند -- نشانش بدهید، رویش تطبیق ندهید
case errors.Is(err, srosha.ErrUnauthorized):
	// کلیدی نیست، یا کلیدی است که srosha نمی‌شناسد
}
```

به ازای هر کدی که srosha جواب می‌دهد یک sentinel هست و نه ریزتر:
`ErrInvalidRequest`، `ErrUnauthorized`، `ErrForbidden`، `ErrNotFound`،
`ErrDuplicate`، `ErrRateLimited`، `ErrUnavailable`، `ErrTimeout`،
`ErrInternal`.

`ErrInvalidRequest` هم آدرسِ بدشکل را می‌پوشاند، هم بدنهٔ خالی، هم بازهٔ بلندتر از
نگه‌داشت. تشخیصشان از هم یعنی تطبیق روی متنِ پیام، که روزی که کسی جمله را
بازنویسی کند می‌شکند — پس **متن را بخوانید، روی sentinel شاخه بزنید.**

### تلاشِ دوباره

کلاینت فقط `ErrUnavailable` و `ErrTimeout` و `ErrRateLimited` را دوباره تلاش
می‌کند. پیش‌فرض سه تلاش، با فاصلهٔ نمایی و jitter.

**تلاشِ دوبارهٔ `Submit` امن است، هرچند چیزی می‌سازد.** `IdempotencyKey` را خالی
بگذارید و یکی برای همان تماس ساخته می‌شود، پس هر سه تلاش **یک** پیام‌اند. دو
`Submit` ــِ جدا دو کلید و دو پیام می‌گیرند — که درست است، چون یک هشدارِ یکسان که
عمداً دو بار فرستاده شود چیزِ واقعی است.

کلیدِ خودتان را وقتی بگذارید که **شما** این تضمین را بینِ تماس‌ها می‌خواهید:

```go
srosha.Message{IdempotencyKey: "order-42", …}
```

دو بار بفرستیدش و دومی با شناسهٔ اولی و `Duplicate: true` جواب می‌دهد. کلیدها
مالِ خودِ شمایند، پس `order-42` ــِ مشتریِ دیگر مالِ شما نیست.

## ۱۰ — اتصال: گزینه‌ها

| | |
| --- | --- |
| `WithInsecure()` | plaintext، برای تماس‌گیرنده‌ای داخلِ شبکهٔ خودِ srosha |
| `WithTLSConfig(*tls.Config)` | یک CA ــِ خودی در staging |
| `WithTimeout(d)` | مهلت، وقتی context ــِ شما مهلتی ندارد. پیش‌فرض ۳۰ ثانیه |
| `WithRetry(n)` | کلِ تلاش‌ها. `1` یعنی بدونِ تلاشِ دوباره. پیش‌فرض ۳ |

یک `Client` اتصال نگه می‌دارد و برای استفادهٔ همزمان امن است. **نگهش دارید** —
ساختنِ یکی به‌ازای هر درخواست، هر کاری که gRPC برای اتصالِ دوباره می‌کند را دور
می‌ریزد.

## مرجع

هیچ چیزی در سطحِ این package از جنسِ protobuf یا gRPC نیست: زمان‌ها `time.Time`
اند، کانال‌ها و اولویت‌ها رشته‌اند، و خطاها چیزی‌اند که `errors.Is` می‌فهمد.
`sdk/go/notification/v1` قراردادِ تولیدشدهٔ زیرین است و اگر این package چیزی را
نپوشانده باشد می‌توانید یک پله پایین بروید — ولی آن یک پله مشمولِ پایداری‌ای که
بقیهٔ این package قول می‌دهد نیست.

طراحی، و آنچه در برابرش رد شد، در
[spec](../../docs/superpowers/specs/2026-08-27-go-sdk-design.md) است.

`v0.x` تا وقتی API جا بیفتد.
