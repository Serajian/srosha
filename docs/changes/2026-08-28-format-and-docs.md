# ۳ — `make format` دو تا `//nolint` را می‌شکست

`golines` خطی را wrap می‌کرد و directive از خطی که gosec گزارش می‌دهد جدا
می‌افتاد:

```go
attempt := int(meta.NumDelivered) //nolint:gosec // …
        ↓ golines
attempt := int(
    meta.NumDelivered,
) //nolint:gosec // …          ←  دیگر روی خطِ درست نیست
```

بارِ قبل فقط برشان گرداندم؛ این بار بسته شد. `//nolint` به خطِ **قبل** رفت، که
golangci-lint قبولش می‌کند و **golines نمی‌تواند از هم جدایشان کند** — چون خطی
برای شکستن نمانده.

هر دو ادعا آزموده شدند، نه فرض:

```
یک خطِ nolint ــِ مستقل        →  golangci-lint: 0 issues
همان، داخلِ composite literal  →  0 issues       ← این یکی مسلّم نبود
golines رویشان اجرا شد          →  هیچ‌کدام عوض نشد
```

# ۴ — و بازفرمتِ ۳۵ فایلی که منتظر بود

`golines` ظاهراً هرگز روی این مخزن اجرا نشده بود. حالا شد:

```
۳۵ فایل، ۲۸۷ افزوده، ۹۱ حذف
```

و آنچه **دست نخورد** مهم‌تر است:

```
sdk/go/notification/v1/     protobuf ــِ تولیدشده
internal/adapter/db/postgres/gen/   sqlc ــِ تولیدشده
```

هر دو دست‌نخورده ماندند. اگر بازفرمت می‌شدند، اولین `make proto` یا `make sqlc`
همه‌اش را برمی‌گرداند و diff ــِ کاذب می‌ساخت.

ترتیب عمدی بود: **اول ۳، بعد ۴.** برعکسش یعنی بازفرمت دوباره همان دو تا
`//nolint` را می‌شکست.

# Follow-ups / Risks

- **`golines` در `make format` است ولی در `prepush` نیست.** یعنی کسی می‌تواند
  کدِ wrap نشده commit کند و هیچ چیز نگیردش تا وقتی کسی `make format` بزند و یک
  diff ــِ بی‌ربط بگیرد. یا باید به `fmt-check` اضافه شود، یا از `make format`
  برداشته شود. نصفه‌بودنش همان چیزی است که این وضع را ساخت.
- **badge ــِ «Go 1.26» با go.mod ــِ SDK نمی‌خواند** که `1.23` است. badge مالِ
  سرویس است و درست، ولی کسی که فقط README را ببیند فکر می‌کند برای SDK هم ۱٫۲۶
  لازم است.
- **`.golangci.yml` دیگر `postgres/gen` را معاف نمی‌کند.** الگوی قدیمیِ `gen`
  به‌عنوان regex آن را هم می‌گرفت؛ الگوی دقیقِ تازه نه. امروز مشکلی نیست چون
  `generated: lax` سربرگِ «Code generated by» را می‌شناسد، ولی این دو ساز و کارِ
  متفاوت‌اند و یکی‌شان بی‌صدا جای دیگری را پوشانده بود.
