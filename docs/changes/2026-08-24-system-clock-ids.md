# Summary

دو فایل یک‌خطی که هر مسیر سیم‌کشی به آن‌ها می‌رسید: ساعت و مولد شناسه. حالا
نوشته شده‌اند، و آخرین چیزی که بین ما و سیم‌کشی gateway بود برداشته شد.

## چرا اصلاً adapter اند

هر دو **حالت محیطی** می‌خوانند — چیزی که domain اجازه ندارد:

```go
// core/shared/clock.go
type (
	NowFunc func() time.Time
	IDFunc  func() ID
)
```

کامنت خودش می‌گوید چرا: «تا domain هیچ‌وقت حالت محیطی نخواند: یک تست به آن یک
زمان ثابت و دنبالهٔ مشخصی از شناسه‌ها می‌دهد». پس پیاده‌سازی‌شان بیرون از core
است و از bootstrap تزریق می‌شود.

## ساعت: UTC، و این سلیقه نیست

```
دو باینری در دو جا  →  یک رویداد را دو جور مهر می‌زنند
expire_at در یک zone نوشته شود  →  با now در zone دیگری مقایسه شود
ساعت رسمی کشوری عوض شود  →  ردیف‌ها با آن جابه‌جا شوند
```

هیچ‌جای این سرویس زمانی را به یک آدم نشان نمی‌دهد، پس هیچ دلیلی برای zone محلی
وجود ندارد.

## شناسه: ULID، و انتخابش باربر است

ده کاراکتر اولش همان میلی‌ثانیه‌ای است که ساخته شده، پس شناسه‌ها **بر اساس زمان
مرتب می‌شوند**. و این دقیقاً همان چیزی است که کل صفحه‌بندی رویش سوار است:

```sql
ORDER BY id            -- ترتیب ساخت، بدون ستون دوم
WHERE id > @after      -- صفحهٔ بعد، بدون offset ای که باید بشمارد
```

با uuid v4 هیچ‌کدام ممکن نبود و کنار هر primary key یک ایندکس روی `created_at`
لازم می‌شد.

## و entropy باید monotonic باشد

اینجا ظرافت واقعی است. دو ULID در **یک میلی‌ثانیه** timestamp یکسان دارند، پس
ترتیبشان را نیمهٔ تصادفی تعیین می‌کند — یعنی تصادفی.

```
پیامی به چهار گیرنده  →  چهار delivery در یک میلی‌ثانیه نوشته می‌شوند
                          بدون monotonic، ترتیبشان قرعه‌کشی است
                          و «مرتب بر اساس id» دیگر یعنی «به ترتیب ساخت» نیست
```

`ulid.Monotonic` تضمین می‌کند شناسهٔ بعدی در همان میلی‌ثانیه اکیداً بزرگ‌تر است.
`TestIDsMadeInOneMillisecondStillOrderByWhichCameFirst` دویست شناسه با ساعت
یخ‌زده می‌سازد و ثابت می‌کند ترتیب ساخت با ترتیب مرتب‌شده یکی است.

و چون reader بین فراخوانی‌ها حالت نگه می‌دارد و gateway هر درخواست را روی
goroutine خودش جواب می‌دهد، **قفل دارد**.

## `crypto/rand`، نه `math/rand`

شناسه به مشتری برگردانده می‌شود و به‌عنوان cursor صفحه استفاده می‌شود. شناسهٔ
قابل‌پیش‌بینی یعنی کسی می‌تواند دنباله را راه برود و بفهمد منبع دیگری چقدر ترافیک
دارد.

## `Generate` نمی‌تواند شکست بخورد، چون port نمی‌تواند

`shared.IDFunc` خطا برنمی‌گرداند. `ulid.New` یک خطا دارد: تمام شدن جای entropy
در یک میلی‌ثانیه، که نیمهٔ تصادفی باید از قبل تماماً یک باشد. جوابش یک شناسهٔ تازهٔ
غیر-monotonic است، نه panic روی یک درخواست زنده — آن شناسه هنوز یکتاست و هنوز به
میلی‌ثانیهٔ درست مرتب می‌شود؛ فقط ترتیبش نسبت به همسایه‌هایش در آن میلی‌ثانیه
دلخواه است.

`crypto/rand` از Go 1.24 اصلاً خطا برنمی‌گرداند — پروسه را می‌کشد به‌جای اینکه
مقداری بدهد که نمی‌تواند ضمانتش کند — پس این مسیر برای دلیلی که ما را زنده بگذارد
شکست نمی‌خورد.
