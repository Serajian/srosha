# Summary

چهار فایلی که نصفِ مسیرِ ورودِ srosha را می‌سازند و تا امروز فقط روی سرور زندگی
می‌کردند، آمدند داخلِ `deployment/infra/`. **هیچ کدِ Go ای عوض نشده و هیچ رفتاری در
production تغییر نکرده** — این‌ها همان چیزی هستند که همین حالا اجرا می‌شوند.

## چرا

امروز سرور عوض شد و این چهار فایل باید از نو ساخته می‌شدند. یک بعدازظهر طول کشید،
از جمله یک انحرافِ طولانی به‌خاطرِ سندی که سرورِ **قبلی** را توصیف می‌کرد.

نکتهٔ اصلی این نیست که وقت گرفت. این است که در تمامِ آن مدت هیچ‌کس نمی‌توانست بخواند
که پیکربندیِ واقعی چیست. پیکربندی‌ای که خوانده نمی‌شود، بررسی هم نمی‌شود.

## چه چیزی آمد

```
deployment/infra/
  README.md
  postgres/docker-compose.yml     postgres 18 + adminer
  nats/docker-compose.yml
  nats/nats-server.conf           سه کاربر و دسترسی‌هایشان
  nginx/srosha.conf               سه server block، جایی که TLS تمام می‌شود
```

هر چهار فایل سرصفحه‌ای گرفتند که با حروفِ درشت می‌گوید **از این repository دیپلوی
نمی‌شوند**. بقیهٔ چیزهای زیرِ `deployment/` خودکار می‌روند؛ این‌ها نه، و این تفاوت آنقدر
مهم هست که دو بار گفته شود.

`README.md` می‌گوید هرکدام با چه چیزی اعمال می‌شود و کجا می‌نشیند — از جمله آن مسیرِ
File Mount که همه یک بار گولش را می‌خورند: `nats-server.conf` است، نه مسیرِ داخلِ
کانتینر. اشتباهش docker را وادار می‌کند به‌جای فایل یک **پوشه** بسازد، و کانتینر با
`exit 127` و لاگِ خالی می‌میرد.

## هیچ رازی داخلشان نیست

هر مقداری که راز باشد یک `${VAR}` یا `$VAR` است. دو تا از آن‌ها هم عمداً بلند شکست
می‌خورند و تستش کردیم:

- `nats-server` با `variable reference for 'NATS_GATEWAY_PASSWORD' ... can not be
  found` خارج می‌شود؛ با رمزِ خالی بالا نمی‌آید.
- پورتِ دومِ adminer `${ADMINER_BIND_IP:?...}` است، چون مقدارِ خالی آن خط را به
  `:8083:8080` تبدیل می‌کند — یعنی `0.0.0.0`، یعنی یک فرمِ ورود به پایگاه داده روی
  اینترنت. با `:?` به‌جایش deploy شکست می‌خورد و می‌گوید چرا.

## `.dockerignore`

`deployment/infra/` کنار گذاشته شد. هیچ‌چیزی در image این‌ها را نمی‌خواند، و مهم‌تر:
بدونِ آن، ویرایشِ یک server block ــِ nginx کشِ build را باطل می‌کرد و deploy ــِ بعدی
یک build کاملِ Go می‌شد — همان ده دقیقهٔ `go mod download`.

## `docs/CONFIG.md`

سه چیز اضافه شد که تا امروز هیچ‌جا ثبت نبود:

- سطرِ `deployment/infra/` در جدولِ مسیرها
- `db.srosha.ir` در جدولِ hostname ها، با توضیحِ اینکه یک نامِ **عمومی** است که به
  آدرسِ Tailscale اشاره می‌کند: نام عمومی است، آدرس از اینترنت route نمی‌شود
- پورتِ ۸۰۸۳، و بازنویسیِ آن جمله که می‌گفت فقط **یک** پورتِ میزبان داریم

و یک معیار که تا حالا نانوشته بود: **`0.0.0.0` هیچ‌جا نباید باشد**، و آزمونش
`docker port <container>` است.
