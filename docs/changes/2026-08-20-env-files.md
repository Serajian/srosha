# Summary

`.env.example` که خالی بود نوشته شد، و `.env` محلی هم ساخته شد. منبع هر دو بخش ۵
سند `docs/reference/srosha-infra-deploy.md` است.

`.env.example` بر اساس اینکه هر کلید مال کدام باینری است بخش‌بندی شده — مشترک،
فقط gateway، فقط dispatcher، و goose. دلیلش این است که config در این پروژه
per-binary است: یک config مشترک باعث می‌شد gateway سر یک توکن تلگرام که هیچ‌وقت
استفاده نمی‌کند، موقع بالا آمدن fail کند.

قانون رمز به‌عنوان کامنت بالای فایل آمد — فقط حرف و رقم و خط تیره — چون سند
می‌گوید این یکی گران تمام شده: یک `#` در رمز توسط parsing فایل `.env` دوکپلوی
بی‌صدا بریده شده بود.

`.env` مقادیر لوکال دارد: postgres روی `127.0.0.1:7001`، nats روی
`127.0.0.1:7002`، دیتابیس و نقش `srosha`، و log level روی `debug`. همهٔ tokenها
خالی‌اند. `.gitignore` این فایل را نادیده می‌گیرد و بررسی شد که واقعاً در
`git status` نمی‌آید.

یک تفاوت عمدی بین این دو: در `.env` لوکال، `NOTIF_MQ_URL` بدون user و password
است چون NATS لوکال auth ندارد. در production هر باینری کاربر خودش را دارد
(`gateway` و `dispatcher`) و سند صریح می‌گوید این دو credential را یکی نکن. این
نکته در `.env.example` نوشته شد.
