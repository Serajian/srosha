```go
// یک بار
c.Credentials.Register(ctx, srosha.Registration{

// هر روز — هیچ credential ای در دید نیست

```

# مسئله‌ای که حل شد

امروز `Register` یک **رشتهٔ JSON** می‌گیرد که شکلش در هر کانال فرق دارد و
هیچ‌جای عمومی مستند نیست:

```
telegram · bale · fcm    هیچ
matrix                   {"homeserver":…}
whatsapp                 {"phone_number_id":…}
email                    {"host":…,"port":…,"username":…,"from":…}
apns                     {"key_id":…,"team_id":…,"topic":…,"environment":…}
```

یک حرفِ اشتباه در `key_id` کامپایل می‌شد و روزها بعد سرِ اولین ارسال می‌شکست.
حالا کامپایلر می‌گیردش.

**این آن ضرب‌کردنی نیست که برای `SendEmail`/`SendTelegram` ردش کردیم.** آن‌ها هفت
متد با بدنهٔ یکسان بودند؛ این‌ها هفت شکلِ واقعاً متفاوت‌اند.

# مجموعه بسته است، ولی سرور می‌تواند بخواندش

```go
type Credential interface {
    Settings() (string, error)   // صادراتی — سرور لازمش دارد
    channel() Channel            // غیرصادراتی
    secret() string              // غیرصادراتی
}
```

دو متدِ غیرصادراتی دو کار می‌کنند: **مجموعه را می‌بندند** (هیچ‌کس بیرون از این
package نمی‌تواند خودش را credential جا بزند) و **راز را نگه می‌دارند** (چیزی که
فقط interface را دارد نمی‌تواند بخواندش).

اولش `settings()` را هم غیرصادراتی گذاشتم و با `export_test.go` بازش کردم —
اشتباه بود: `_test.go` فقط برای تست‌های خودِ SDK کامپایل می‌شود و **سرور
نمی‌بیندش**.

# تستی که کلِ این چیدمان برایش بود

```
sdk/go        APNsCredential{…}.Settings()   →  json
                        ↓
main module   apns.ParseConfig(json)          →  باید رد شود
```

چهار کانال (سه‌تای دیگر تنظیمات ندارند)، به‌علاوهٔ تطبیقِ نامِ هر هفت کانال.

**و ثابت کردم که واقعاً می‌گیرد**: عمداً `phone_number_id` را به `phone_id` عوض
کردم —

```
FAIL  whatsapp.ParseConfig: INVALID_INPUT: whatsapp settings have no phone number id
```

یک حرف، و تست می‌گیردش. با مخزنِ جدا این تست ممکن نبود.

# یک تصمیم که در تست عوض شد

اول نوشتم SDK وقتی `Environment` خالی است، `production` بفرستد. **غلط بود**:
پیش‌فرض مالِ سرویس است. کلاینتی که خودش تصمیم بگیرد، جای دومی است که باید عوض
شود روزی که سرویس نظرش عوض شود.

پس SDK خالی می‌فرستد، و اینکه `production` می‌شود در سمتِ سرور تست دارد.

و همهٔ فیلدها هر بار می‌روند، حتی خالی‌ها — چون `Update` کلِ سند را جایگزین
می‌کند نه patch، و حذفِ فیلدِ خالی یعنی «دست نزن» و «پاکش کن» یک درخواست شوند.

# هیچ credential ای رازش را چاپ نمی‌کند

هر هشت نوع `String()` دارند و `json:"-"` — و تست هر دو راه را می‌بندد:

```go
fmt.Sprintf("%v %s %+v", cred, cred, cred)   بدون راز
json.Marshal(cred)                            بدون راز
```

کاری است که برایش وجود دارند. با خاموش کردنشان:

می‌کند. `.env` برگردانده شد.

# Follow-ups / Risks

- **`Update` هنوز می‌تواند گمراه کند.** یک credential ــِ کامل می‌گیرد و فقط
  نیمهٔ تنظیماتش را می‌فرستد؛ رازی که رویش گذاشته شود بی‌صدا نادیده می‌شود. در
  مستند و در تست ثبت است، ولی مانعِ ساختاری نیست. شکستنِ هر نوع به دو نیمه
  هزینه‌اش دو برابر شدنِ هفت نوع بود برای متدی که به‌ندرت صدا زده می‌شود.
- **تأیید امضای webhook هنوز نیست.** `Webhooks.Register` در مستندش صریح می‌گوید
  که این package امضا را برایت چک نمی‌کند. اولین کاندیدِ نسخهٔ بعد.
- **تستِ متقابل سه کانال را پوشش نمی‌دهد** — telegram، bale و fcm تنظیمات ندارند،
  پس چیزی نیست که از هم جدا بیفتد. اگر روزی یکی‌شان تنظیمات بگیرد، باید اضافه شود
  و هیچ چیز یادآوری نمی‌کند.
- **قدمِ ۴ مانده**: `CONVENTIONS.md`، و اولین tag.
