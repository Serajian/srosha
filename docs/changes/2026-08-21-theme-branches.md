Branch: `feat/infra-layer`

# Summary

قانون branch naming در `docs/CONVENTIONS.md` یک حالت را پیش‌بینی نکرده بود و اجازه
داد وضعی پیش بیاید که خودش آن را غلط اعلام می‌کرد.

نوشته بودیم «slug برنچ و slug گزارش یک رشته‌اند» و «یک برنچ، یک تغییر». با این دو،
برنچی مثل `feat/infra-layer` که سه infra را در سه commit مستقل جلو می‌برد، برنچی
می‌شد که «گزارشش نوشته نشده» — چون گزارش‌هایش `infra-messagequeue` و
`infra-httpclient` و `infra-telemetry` هستند، نه `infra-layer`.

خودِ کار درست بود: سه تکنولوژی مستقل، هر کدام باید جدا مرور شوند، ولی هر سه یک
موضوع‌اند و یک merge request می‌خواهند.

بند «یک برنچ، یک تغییر» عوض شد تا «یک تغییر» یعنی **آنچه در یک merge request می‌نشیند**،
نه یک commit. برنچی که چند commit مستقل را زیر یک موضوع جمع می‌کند مجاز است، به این
شرط که هر commit همچنان گزارش خودش را بیاورد. آن‌وقت slug اسم موضوع را می‌گوید و
گزارش‌ها اسم commit ها را.

آنچه عوض **نشد**: اگر slug به «and» احتیاج داشته باشد، هنوز دو برنچ است.
`feat/nats-and-grpc` دو تاست. آن محدودیت اسم عمداً یک محدودیت اندازه هم هست و سر
جایش ماند. و چون گزارش‌ها همچنان به‌ازای commit اند، چیزی از حافظهٔ پروژه کم نشد.
