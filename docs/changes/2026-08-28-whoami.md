Branch: `feat/sdk-whoami`

# Summary

**یک rpc که می‌گوید تو کی هستی و چه اجازه‌ای داری.**

سؤال این بود که آیا SDK نباید یک `Ping` داشته باشد تا source بتواند چک کند
srosha بالاست و کلیدش درست است. جواب: بله — ولی نه `Ping`.

# چرا `Whoami` و نه `Ping`

یک `Ping` فقط «بله» می‌گوید. همان تماس می‌تواند **دو چیزی را هم بگوید که امروز
فقط با اشتباه کردن فهمیده می‌شوند**:

```
سقفِ اولویت    فقط وقتی downgraded=true بگیری
مدتِ نگه‌داشت   فقط وقتی List رد شود
```

زنده نشانش دادم، روی استقراری با نگه‌داشتِ ۷ روزه:

```
Whoami می‌گوید      max window: last_week
اگر گوش ندهی        LastMonth  →  this service keeps messages for 7 days

Whoami می‌گوید      ceiling: high
اگر گوش ندهی        CRITICAL   →  got high, downgraded=true
```

# ارزشِ اصلی: **زمانِ فهمیدن**

`New` به هیچ‌کس وصل نمی‌شود — gRPC تنبل وصل می‌شود. پس آدرسِ غلط یا کلیدِ غلط سرِ
**اولین Submit** معلوم می‌شود، که ممکن است ساعت‌ها بعد باشد، در production، روی
پیامی که مهم بوده.

`Whoami` آن لحظه را به بالا آمدن منتقل می‌کند.

# سرویسِ خودش، و لوله‌کشیِ تقریباً هیچ

`SourceService`، چون هیچ چیز را مدیریت نمی‌کند: بقیه به نامِ اسمی که مالکش‌اند
نام‌گذاری شده‌اند — notification، credential، webhook — و این دربارهٔ **کسی است
که می‌پرسد**. زیرِ هرکدامشان می‌رفت، جایی می‌شد که کسی دنبالش نمی‌گردد.

و handler هیچ repository ای لمس نمی‌کند:

```
احراز هویت از قبل سطر را آورده  →  SourceFrom(ctx) کلِ source را دارد
دو عدد از config                →  bootstrap می‌دهد، مثلِ هر چیزِ دیگر اینجا
```

پرسیدنِ دوباره یعنی یک کوئریِ دوم برای چیزی که در دست است — و این‌طور، جواب
نمی‌تواند به شکلی کهنه باشد که خودِ درخواست نبوده.

# `retention` یک Duration است نه یک Window

```
استقرارِ ۱۰ روزه   →  هیچ Window ای نمی‌گوید «۱۰ روز»
                     گرد کردن اینجا، آن ۴ روزی را که هنوز می‌شد پرسید پنهان می‌کرد
```

پس عددِ صادقانه می‌رود، و SDK با `MaxWindow()` به نزدیک‌ترین پنجرهٔ قابلِ قبول
گردش می‌کند. تست شد که ۱۰ روز → `LastWeek` و یک دقیقه → `Everything`.

# `default_addresses` با نامِ کانال کلید می‌خورد

کلیدِ map در proto3 نمی‌تواند enum باشد — و همین اتفاقاً درست هم هست: نام باعث
می‌شود سرویسی که کانالی تازه یاد گرفته، برای build ــِ قدیمی‌ترِ مشتری نشکند.
همان غریزه‌ای که `Channel` را در SDK رشته کرد.

# `withSource` باز نشد

تست به گذاشتنِ یک source روی context نیاز داشت، ولی آن تابع عمداً غیرصادراتی
است:

> a handler that could be handed one by its caller would be a handler whose
> identity check can be bypassed

پس تست `package grpcsrv` شد، همان کاری که `interceptors_test.go` و
`mapper_test.go` از قبل می‌کنند. مرزِ امنیتی برای راحتیِ تست باز نشد.

# چیزی که این کار آشکارش کرد

`option go_package` در چهار فایلِ proto هنوز `gen/` را می‌گفت. managed mode در
`buf.gen.yaml` موقع تولید override اش می‌کرد، پس هیچ چیز نشکسته بود و کدِ
تولیدشده درست بود — ولی خطوط غلط مانده بودند از قدمِ اولِ SDK.

`source.proto` مسیرِ درست را نوشت، و buf lint فوراً گرفت:

```
Files in package "notification.v1" have multiple values for option "go_package"
```

هر چهارتا اصلاح شدند.

# Follow-ups / Risks

- **`Whoami` از سهمیهٔ rate limit کم می‌کند**، و این عمدی است — وگرنه یک endpoint
  ــِ رایگان برای کوبیدن می‌شد. ولی یعنی اگر کسی روی تایمر صدایش بزند، سهمیه‌اش
  را خرج کرده. مستند صریح می‌گوید «سرِ راه‌اندازی، نه روی تایمر»، و هیچ چیز
  جلویش را نمی‌گیرد.
- **`rate_limit_per_minute` عددِ پیکربندی است نه باقی‌مانده.** نمی‌گوید چقدر از
  سهمیه‌ات مانده. اگر روزی لازم شد، یک فیلدِ دیگر است.
- **هر SDK در هر زبانی باید این را پیاده کند.** سطحِ API تازه است.
- **این برنچ از `feat/sdk-module` بریده شده، نه از master** — نیمهٔ SDK اش به
  کدی نیاز دارد که هنوز merge نشده. باید بعد از آن merge شود.
