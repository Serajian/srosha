Branch: `fix/go-proxy-reachable`

# Summary

deploy ــِ دوم یک قدم جلوتر شکست:

```
proxy.golang.org/github.com/klauspost/compress/@v/v1.18.5.zip: 403 Forbidden
```

همان بیماریِ قبلی. اول `gcr.io` بود، حالا `proxy.golang.org` — سرور به
سرویس‌های گوگل نمی‌رسد.

مالک یک Dockerfile ــِ کارآمد از اپِ دیگری فرستاد و گفت از mirror ها استفاده
شود. سه چیزش برداشته شد.

# `|` به‌جای `,` — این تنها اصلاحِ واقعی است

```
GOPROXY=https://go.devneeds.ir|https://proxy.golang.org|direct
```

با **کاما**، Go فقط روی ۴۰۴ و ۴۱۰ به ورودیِ بعدی می‌رود. روی ۴۰۳ یا قطعیِ
شبکه **می‌ایستد**. یعنی نسخه‌ای که اول نوشته بودم (`goproxy.cn,goproxy.io,direct`)
با همان ۴۰۳ می‌مرد و هرگز به `direct` نمی‌رسید — یک اصلاحِ ظاهراً درست که هیچ
چیزی را درست نمی‌کرد.

با `|` روی **هر** خطایی به بعدی می‌رود، و فهرست به `direct` ختم می‌شود که از
خودِ مخزن‌ها می‌گیرد. GitHub در دسترس است — clone شدنِ همین repo آغازِ build
است.

# حلقهٔ mirror برای apk

از مثال برداشته شد، با دو جزئیاتِ خوبش:

**`timeout` دورِ هر تلاش.** mirror ــِ مسدود قطع نمی‌شود، **معلق می‌ماند**.
بدونِ این، build ده دقیقه هنگ می‌کند به‌جای اینکه سریع رد شود.

**نسخهٔ Alpine از `/etc/alpine-release` خوانده می‌شود، نه نوشته.** و همین
همان‌جا یک اشتباه گرفت: خروجی نشان داد stage ــِ build روی **v3.24** است و
stage ــِ runtime روی **v3.22**. `golang:1.26-alpine` پایهٔ متفاوتی دارد. اگر
نسخه دستی نوشته می‌شد، stage ــِ اول به repository ــِ غلط اشاره می‌کرد.

# یک تفاوت با مثال

در stage دومِ مثال فقط `ca-certificates` نصب می‌شود. مالِ ما `tzdata` هم لازم
دارد: `RECONCILE_SCHEDULE` و `RETENTION_SCHEDULE` هر دو UTC خوانده می‌شوند و
container ــِ بدونِ پایگاهِ منطقه نمی‌تواند این را بگوید.

`GOSUMDB=off` هم آمد، با توضیح در خودِ فایل که چه از دست می‌رود: `go.sum` در
مخزن است و هر ماژول همچنان با آن تأیید می‌شود. آنچه می‌رود، نظرِ دومِ
sum.golang.org است دربارهٔ ماژول‌هایی که در `go.sum` **نیستند** — و چنین
ماژولی وجود ندارد، چون `go mod download` همان فایل را می‌خواند.

هر دو base image و هر دو متغیرِ proxy `ARG` اند، پس هاستی با mirror های دیگر
بدونِ ویرایشِ فایل مالِ خودش را پاس می‌دهد.

# Tests Run

**آنچه ثابت شد**، روی این ماشین:

- هر دو حلقهٔ apk سبز رد شدند، از mirror ــِ اول
- نسخهٔ Alpine درست استخراج شد: `v3.24` در build و `v3.22` در runtime
- همهٔ مرحله‌های COPY گذشتند
- `make precommit` — pass

**آنچه ثابت نشد، و از اینجا نمی‌شود:** خودِ فهرستِ proxy. `go.devneeds.ir` از
اینجا کند است و build روی `go mod download` ماند. این دربارهٔ سرور چیزی
نمی‌گوید — آنجا همان mirror نزدیک‌ترین است. نتیجهٔ build ــِ محلی تأییدِ آنچه
اهمیت دارد نیست، چون شبکه‌ها فرق دارند.

تنها تستِ معنادار، deploy ــِ بعدی است.

# Follow-ups / Risks

- اگر `go.devneeds.ir` هم روی سرور جواب نداد، `|` کارش را می‌کند و به
  `proxy.golang.org` و بعد `direct` می‌رود. `direct` باید همیشه کار کند چون
  GitHub در دسترس است.
- الگو حالا روشن است: هرچه از گوگل است روی آن سرور مسدود است. اگر جای دیگری
  `googleapis.com` یا `storage.googleapis.com` لازم شد — FCM چنین چیزی است —
  همان‌جا هم خواهد شکست. FCM هنوز تست نشده.
