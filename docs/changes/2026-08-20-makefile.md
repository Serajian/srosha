# Summary

`Makefile` که خالی بود، از روی Makefile یک پروژهٔ دیگر (odin) نوشته و برای این
پروژه تطبیق داده شد. ساختار help گروه‌بندی‌شده و رنگ‌ها و اسکریپت پیداکردن
`golangci-lint` v2 عیناً نگه داشته شدند.

تطبیق‌های اصلی:

**دو باینری به‌جای یکی.** odin یک `./main.go` داشت؛ اینجا `cmd/gateway` و
`cmd/dispatcher` است. `make build` هر دو را در `build/` می‌سازد، و
`build-gateway` و `build-dispatcher` جدا هم هستند. run و docker image هم همین‌طور.

**بخش proto جای swag را گرفت.** اینجا gRPC است نه REST دستی: `proto`،
`proto-lint`، `proto-breaking` روی `buf`.

**goose جای `migrate` را گرفت**، مطابق SPEC. `migrate-status` و `migrate-create`
با `-s` (شماره‌گذاری ترتیبی) اضافه شدند.

**یک target تازه: `arch-check`.** importهای مستقیم `internal/core/domain/...` را
می‌گیرد و اگر چیزی جز stdlib و `core/shared` و `pkg/errs` ببیند fail می‌کند. در
`precommit` و `prepush` هم گذاشته شد.

چیزهایی که حذف شدند چون در این repository وجود ندارند: `gen-ports`،
`docker-hard-reset` و پاک‌کردن `volumes/` و `init/` — همه به
`scripts/gen-ports-env.sh` وابسته بودند. جایشان `docker-del` مستقیم `down -v`
می‌زند.

چیزهایی که guard خوردند: `git-precommit` اگر `.githooks/` نبود رد می‌شود، و
`test-integration` اگر `tests/integration/` نبود skip می‌کند.

جزئیات ریز: `gci` از `github.com/Serajian/srosha` به‌عنوان prefix استفاده می‌کند
نه از `APP_NAME` (در odin این دو یکی بودند)، و `misspell` مسیر `gen/` را رد می‌کند
چون کد تولیدشده است.

بعد از رسیدن سند infra، سه چیز که غلط حدس زده بودم اصلاح شد: یک image به‌جای دو
image (سند صریح است که هر دو باینری در یک image می‌نشینند و با `command` انتخاب
می‌شوند، تا هرگز روی دو commit مختلف نیفتند)، مسیر compose به
`deployment/app/docker-compose.yml`، و نام دیتابیس و کاربر به `srosha`/`srosha`.
`BASE_PORT` هم `7000` شد و `GRPC_PORT` حالا از `NOTIF_GRPC_ADDR` در `.env`
خوانده می‌شود با fallback به `50051`.

# Follow-ups / Risks

- `make build` fail می‌شود با `function main is undeclared in the main package`.
  `cmd/gateway/main.go` و `cmd/dispatcher/main.go` فایل‌های خالی‌اند. این از قبل
  این‌طور بوده و ربطی به Makefile ندارد.
- نسخهٔ اول `arch-check` با `go list -deps` نوشته شده بود (همان یک‌خطی SPEC) و غلط
  بود: `net/mail` به‌طور ترانزیتیو `net` و `mime` و `log` را می‌آورد و همه را
  false positive می‌داد. با import مستقیم بازنویسی شد.
- targetهای docker به `deployment/app/` اشاره می‌کنند که هنوز خالی است.
- `arch-check` فعلاً اجازه می‌دهد packageهای domain همدیگر را import کنند، چون
  امروز `notification` به `source` وابسته است. اگر تصمیم باز §19 سند SPEC طور
  دیگری حل شود، این check باید سخت‌گیرتر شود.
