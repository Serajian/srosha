Branch: `feat/ratelimit`

# Summary

`source.RateLimiter` از قبل در core تعریف شده بود و `Admit` صدایش می‌زد، ولی هیچ
پیاده‌سازی‌ای نداشت — `adapter/ratelimit/memory.go` یک خط بود. حالا دارد.

## چرا سطل ژتون، نه شمارش در دقیقه

ساده‌ترین راه پنجرهٔ ثابت است: بشمار، سر دقیقهٔ بعد صفر کن. و همان‌جا خراب می‌شود:

```
سقف ۶۰۰ در دقیقه، پنجرهٔ ثابت:

11:59:00 ─────────────── 12:00:00 ─────────────── 12:01:00
                    ▲          ▲
                 ۶۰۰ تا      ۶۰۰ تا
                    └── ۱۲۰۰ درخواست در دو ثانیه ──┘
```

هر دو پنجره قانونی‌اند و سرویس دو برابر سقف را در یک لحظه خورده است. این باگ نیست،
خاصیت پنجرهٔ ثابت است.

سطل ژتون لبه‌ای برای ایستادن ندارد:

```
ظرفیت = ۶۰۰       ← یک batch طبیعی رد نمی‌شود
پر شدن = ۶۰۰ در دقیقه (۱۰ در ثانیه)  ← بلندمدت سقف رعایت می‌شود
```

`TestThereIsNoWindowEdgeToStandOn` دقیقاً همین را می‌گیرد: بعد از خرج کردن کل سهمیه،
یک ثانیه بعد **ده تا** مجاز است، نه ششصدتا.

## ظرفیت = کل سهمیه، نه یک ثانیه

این تنها تصمیم محصولی اینجاست. برای یک سرویس اعلان، انفجار **حالت عادی** است — یک
کمپین، یک حادثه که هزار هشدار می‌سازد. اگر ظرفیت ۱۰ بود (یک ثانیه)، یک ارسال گروهی
۲۰تایی وسط راه رد می‌شد.

## حافظه: نظافتی که هیچ تنظیمی ندارد

map با کلید `sourceID` رشد می‌کند. راه‌حل معمول یک TTL است، یعنی یک عدد تنظیمی دیگر
که باید درست حدس زده شود. ولی سطل ژتون یک خاصیت دارد:

```
سطلی که پُر شده  ≡  سطلی که هرگز وجود نداشته
        ↓
پس هر ورودیِ پُر را می‌شود دور انداخت — هیچ جواب آینده‌ای عوض نمی‌شود
```

پس نظافت **نمی‌تواند اشتباه تنظیم شود**. تنها چیزی که `sweepEvery` تعیین می‌کند این
است که دو عدد یک منبع بیکار چقدر بماند، نه اینکه جوابی عوض شود.

دو تست این را از دو طرف می‌بندند: منبع بیکار فراموش می‌شود و با سهمیهٔ کامل برمی‌گردد
(همان چیزی که به‌هرحال داشت)، و منبعی که سطلش خالی است **فراموش نمی‌شود** — وگرنه
سهمیه‌اش با هر بار جاروکردن ریست می‌شد.

نظافت داخل خودِ `Allow` اجرا می‌شود نه در یک goroutine. goroutine یعنی چیزی که باید
بسته شود، یعنی جایی در `registry` با tier و `Close` — تشریفات زیادی برای راه رفتن
روی یک map.

## `golang.org/x/time/rate`

به‌جای نوشتن سطل خودمان. `AllowN(now, 1)` ساعت را از بیرون می‌گیرد، پس تست می‌تواند
یک ساعت جلو برود به‌جای اینکه یک ساعت صبر کند، و `TokensAt(now)` همان چیزی است که
نظافت لازم دارد.

## چیزی که باید صریح گفته شود

**per-instance است.**

```
یک gateway   →  سقف واقعی = ۶۰۰
دو gateway   →  سقف واقعی = ۱۲۰۰   ← هر کدام سطل‌های خودش را دارد
```

پذیرفته شده، چون یک instance بالاست. در کامنت تایپ نوشته شده تا کسی سرش کلاه نرود، و
روزی که instance دوم بالا بیاید تنها همین فایل عوض می‌شود.
